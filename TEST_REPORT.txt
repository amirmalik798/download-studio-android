DOWNLOAD STUDIO ANDROID v0.1.3 — SOURCE VALIDATION

Changes:
- Removed floating overlay service and associated SYSTEM_ALERT_WINDOW, Usage Access, and foreground-service permissions.
- Registered ACTION_SEND text/plain for YouTube shared URLs; the app asks Video or Audio after receiving the URL.
- Added YouTube thumbnail previews and visible VIDEO/AUDIO type labels to the shared queue/library row component.
- Set concurrency to one by default and maximum two; yt-dlp concurrent fragments limited to one.
- Added Android thermal status guard (API 29+): hold new jobs at MODERATE and interrupt/requeue active work at SEVERE+ until the phone cools.
- Added two-second monitor interval, tail-only log reads, 15-minute inactivity timeout and six-hour maximum runtime.
- Added a sleep-based Termux watchdog so inactivity/runtime limits continue while yt-dlp is running outside the app UI.
- Replaced perpetual Settings polling with a bounded 15-second engine check.
- Added YouTube thumbnail fallback and updated developer credit/version 0.1.3.

Static validation: included in GitHub Actions; pending new run.
Kotlin syntax scan: pending remote build. Full Android compilation requires Gradle and Android SDK.
Physical-device tests: not yet performed. Validate thermal pause/resume, Share-sheet routing, thumbnail display and a long-running paused download on the target Samsung phone.

Limitations:
- No software can guarantee zero device heating. FFmpeg and yt-dlp still use CPU, battery, storage and network when downloading/processing.
- Android thermal status is available through the public API on Android 10+; OEM reporting varies. Older Android versions rely on the one-download default and two-download cap.
- Download Studio registers as a share target but cannot force Samsung/Android to rank it first.
- Static validation is not an APK malware scan or certification.
