DOWNLOAD STUDIO ANDROID v0.1.4 — SOURCE VALIDATION

Changes:
- Consolidated Queue and Library into one Downloads destination; persisted download records are retained.
- Added name search, A–Z and Z–A sorting, newest and oldest download-date sorting, and All/Video/Audio filters.
- Added completion timestamp persistence for new completions; legacy records without a completion timestamp use their creation date as a fallback.
- Added yt-dlp DS_TITLE metadata output and updates the persisted item title from the real media title.
- Existing generic Shared media entries use their output filename as a visible title fallback where possible.
- Completed row taps resolve the file within the user's selected SAF folder and launch Android ACTION_VIEW with a detected MIME type and temporary read permission.
- Active/queued/failed rows continue to open their details and controls.
- Version bumped to 0.1.4 / version code 5.

Static source checks are included in GitHub Actions. APK compilation is not claimed until the workflow succeeds.
Physical device tests still required for all four sort options, search, category filters, YouTube title metadata, legacy-title fallback, and opening MP4/MP3 files with installed default apps.

Existing thermal and runaway safeguards are retained: one download by default, two maximum, one yt-dlp fragment, Android thermal-status guard, 15-minute inactivity timeout, six-hour maximum runtime, tail-only log reads, and bounded Termux watchdog.

Limitations: no software can guarantee zero device heating; Android file opening depends on installed compatible apps and SAF permission grants; legacy download completion dates were not recorded historically.
